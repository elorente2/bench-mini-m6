# Results — Mac mini M6 32 GB, November 2026

Test set: **Qwen3.8-27B**, suite revision **5**, clean passes with validated
cache cases. Splash and Mirai were measured on 2026-11-05; both Ollama labels
on 2026-11-06.

- Splash 1.5.0: `unsloth/Qwen3.8-27B-GGUF:UD-Q3_K_XL`, Q3_K_XL (~3-bit),
  13.1 GB + DFlash2 draft 3.8 GB.
- Mirai/uzu 0.6.17: `alibaba:qwen3.8:27b:mirai:mirai-m:4`, 4-bit, 14.5 GB +
  speculator 1.1 GB.
- Ollama 0.40.14, imported label: `qwen3.8-27b-q3kxl`, Q3_K_XL GGUF, 32K
  context, llama.cpp runner.
- Ollama 0.40.14, native label: `qwen3.8:27b`, nvfp4, 32K context, MLX runner.
- Machine: Mac mini M6, 32 GB (34.4 GB reported), macOS 27.2, Python 3.15.2.

## Interpretation

- **Text and code agents:** Mirai/uzu. It wins short decode (60.8), prefill
  (530.7), cold TTFT (34.1 s) and cached TTFT (250 ms), and uses 19.63 GB peak
  wired. Splash wins long-context decode (44.8 vs 39.6).
- **Long-context decode:** Splash is 13% ahead in this pass. This is a
  single repetition measured while generating 128 tokens after a cache hit; the
  legacy suite had the opposite result, so do not over-rank on this row.
- **Ollama native:** about 2x faster than the imported Q3_K_XL label, but still
  roughly half the short-decode speed of Splash/Mirai and the heaviest wired
  footprint (24.85 GB). It is the right choice only if you need Ollama
  integration or its tools/vision path.
- **Ollama imported Q3_K_XL:** the same Q3_K_XL weights as Splash run about 5x
  slower (11.0 vs 56.3 tok/s) and take twice as long to cold-prefill (85.3 vs
  41.0 s). It has the lowest peak wired memory (16.16 GB), but the speed cost is
  too large for interactive agent work.
- **Prefix cache:** all four engines validate. Mirai is fastest at 250 ms,
  followed by Splash (463 ms), Ollama native (510 ms) and Ollama Q3_K_XL
  (830 ms).
- **Vision, PDF and verified long context:** Splash. It reports 217,081 tokens
  and accepts images/PDFs. Ollama native advertises vision and tools but was
  only tested as text at 32K. Mirai's M model is text-only.

## Caveats

- **Speed, not quality.** Splash and Ollama Q3_K_XL use Q3_K_XL; Mirai uses
  4-bit M; Ollama native uses nvfp4. A quality comparison needs identical
  weights and a separate evaluation set.
- **Ollama context is 32K.** The long prompt is ~18K, so both labels fit, but
  this is not a 217K-context comparison.
- **One repetition for long-context decode.** The 13% Splash advantage is not
  yet a robust ranking.
- **One machine, one thermal state.** Results are specific to this Mac mini.
- **Peak RSS is not comparable across engines** when Metal allocations are
  wired. Use peak wired memory for the memory verdict.

## What is still pending

2. >100K context stress test for Splash.
3. Image/PDF checks for Splash and Ollama native (not throughput).
4. A same-weights quality evaluation, which is a different benchmark.
