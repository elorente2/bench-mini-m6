# Results — Mac mini M6 32 GB, November 2026

Test set: **Qwen3.8-27B**, suite revision **5**, clean back-to-back passes.
Both cache cases validate.

- Splash 1.5.0: `unsloth/Qwen3.8-27B-GGUF:UD-Q3_K_XL`, Q3_K_XL (~3-bit),
  13.1 GB + DFlash2 draft 3.8 GB.
- Mirai/uzu 0.6.17: `alibaba:qwen3.8:27b:mirai:mirai-m:4`, 4-bit, 14.5 GB +
  speculator 1.1 GB.
- Ollama 0.40.14: configured, not measured in this result set.
- Machine: Mac mini M6, 32 GB (34.4 GB reported), macOS 27.2, Python 3.15.2.

## Interpretation

- **Text and code agents:** Mirai/uzu. It wins short decode (+8%), prefill
  (+20%), cold TTFT (−17%) and cached TTFT (−46%), and uses less wired memory.
- **Long-context decode:** Splash was 13% faster in this pass (44.8 vs
  39.6 tok/s). This is a single-repetition metric measured while generating 128
  tokens after a cache hit. The legacy suite had the opposite result (37.8 vs
  45.5), so do not treat it as a stable win without more repetitions.
- **Prefix cache:** both engines now hit. Splash reuses the 18,091-token prefix
  and takes 463 ms to first token; Mirai takes 250 ms.
- **Vision, PDF and verified long context:** Splash. It accepts images and
  PDFs and reports 217,081 tokens. Mirai's M model is text-only and does not
  report a context window; this benchmark only exercised 18K.
- **Ollama:** pending. The verdict can change if either Ollama label is faster
  or uses less memory, especially the imported Q3_K_XL label that isolates the
  engine from the weights.

## Why this differs from the legacy run

The original `jarvis/bench-llm` result had Splash at 56.1/37.8/446 and Mirai at
63.0/45.5/532. The new suite fixes three things:

1. The cold turn now finishes naturally (`finish=stop`). A turn truncated by
   `max_tokens` left Mirai's prefix cache in a non-extensible state, which is
   why its legacy cached TTFT was 35.0 s and invalid.
2. The cached case extends the exact cold prefix with a fixed assistant turn
   and a 128-token follow-up, so the cache hit and the long-context decode are
   measured in the same request.
3. `decode_short` and the long-decode run are recorded with their actual
   completion token counts. Mirai's legacy cold run used 128 output tokens
   while Splash used 8.

The legacy numbers remain archived; do not mix them with suite-v5 results.

## Caveats

- **Speed, not quality.** Splash runs Q3_K_XL and Mirai runs 4-bit M weights.
  A quality comparison needs identical weights and a separate evaluation set.
- **Context is advertised, not verified.** No >100K stress test was run.
- **One repetition for long-context decode.** The 13% Splash advantage is
  interesting but not yet a robust ranking.
- **One machine, one thermal state.** Results are specific to this Mac mini.
- **Peak RSS is not comparable across engines** when Metal allocations are
  wired. Use peak wired memory for the memory verdict.
